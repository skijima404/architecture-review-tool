# Prompt Sequence: Detail Report Triggering

This document defines the purpose and behavior of the `Detail Report Triggering` prompt, which is used during Step 9 of the architecture review workflow.

---

## 🧠 Role Transition

The AI shifts from broad review synthesis and action generation (Steps 6–8) into deep-dive mode. It now takes a single high-impact issue or advisory and expands it into a standalone report suitable for stakeholder communication or future reference.

---

## 🎯 Objective

To produce a detailed, standalone explanation of a specific architectural concern or advisory item. The output is typically used for:

- Communicating risks and rationale to non-technical stakeholders
- Supporting justification of upcoming decisions
- Documenting the reasoning behind future ADR or AAR items

---

## 📦 Inputs Expected Before Triggering

- A prioritized list of findings or action items (initially from Step 6's generate-summary; refined version incorporating context from Steps 7–8)
- Identification of a specific item requiring deeper explanation
- Any related artifacts (e.g., GraphDB node ID, AAR link, architectural diagram snippet)

---

## 📝 Output Contents

The output is a detailed markdown document with the following structure:

- Title (derived from the issue)
- Context (why this matters, what is at risk)
- Reasoning and supporting evidence
- Consequences if unaddressed ("Realistic Consequence")
- Recommended resolution (if known)
- Related AAR or ADR references

---

## ✅ Output Format Location

Detail reports generated by this prompt are now written in the Architecture Advisory Record (AAR) format.

Outputs are stored in:

```
/workspace/architecture-review-tool/aar/aar-XXXX.md
```

Each file should include a frontmatter block for traceability, such as:

```yaml
related_symptoms: [rf-001, rf-008]
related_root_causes: [rc-012]
related_success_criteria: [sc-004]
```

This allows AARs to be linked directly to graph-based backcasting elements and reviewed in downstream architecture workflows.

---

## 💡 Notes

- This mode may be invoked manually after Discussion or Action Extraction
- Multiple detail reports may be generated in a single review session
- The report may later be referenced or embedded in ADRs, AARs, or review records
